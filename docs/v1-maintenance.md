## Shared Characteristics

All v1 prompts share these principles (derived from superpowers skills):

1. **5-phase chain**: brainstorm -> plan -> implement -> completion/integration check -> final acceptance review -> receive-review
2. **TDD cycle**: write failing test -> run -> implement -> run -> commit
3. **Review cadence**: per-agent completion/integration check after each returned implementer; one unified final acceptance review after all plan tasks complete; full spec/code-quality reviewer loop is not run automatically after every subtask
4. **Fresh subagent per task**: each implementation task gets a clean subagent
5. **No performative agreement**: no "You're right!", no "Great point!"
6. **No placeholders**: plans must have zero TODO/TBD/placeholder
7. **Bite-sized tasks**: 2-5 minute steps in plans
8. **Investigate before claiming**: never speculate about unread code
9. **Parallelize reads**: batch independent file reads
10. **Deepwork tag envelope**: every `prompts/v1/deepwork/*.md` file, including `claude-opus-5.md`, is wrapped in exactly one `<deepwork-mode>` envelope to match the omo prompt envelope while keeping `v1` only as the config/path label. The parallel Codex source begins its applicability guard before its guarded ahead-of-runtime carriage.
11. **No model-visible version label**: files under `prompts/v1/` must not mention `v1` to the model. Use `deepwork` wording in model-facing prompt text.
12. **Concrete category scope**: category prompts describe the work shape and deliverable they handle, not vague model strength or weak/strong capability levels. Local mapping: `hard-reasoning` covers ultrabrain-style decisions, `deep` covers autonomous system development and feature delivery, `coding` covers determined code edits and bug fixes, `normal-task` covers bounded fallback work with known acceptance criteria, `complex` covers coordinated multi-step or cross-cutting ordinary tasks that remain below autonomous feature delivery, and `documenting` covers standalone text.
13. **Reasoning defaults**: built-in category defaults from `coding` upward should use `max` in the local variant vocabulary. GPT-5.6 supports native `max`; other families use their selected model's maximum-effort control when available. `quick` remains lightweight. User-declared model, variant, and provider parameters are respected as explicit configuration except for review/plan-review floors.
14. **Flat delegation graph**: effective prompt contracts and granular task permissions terminate at utility leaves; planner returns difficult-decision blockers to the orchestrator, and no role transfers formal review ownership away from the orchestrator.
15. **Shared destructive-command safety**: every assembled built-in agent and category prompt receives exactly one workflow-independent shell-safety block; model-specific prompt files do not duplicate it.
