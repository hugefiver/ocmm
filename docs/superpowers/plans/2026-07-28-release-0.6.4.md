# ocmm 0.6.4 Main Package Release Implementation Plan

> **For agentic workers:** Use the subagent-driven-development skill to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the already-approved `master` release candidate as main package `ocmm@0.6.4`, with two local release commits, immutable tag `v0.6.4`, complete local gates, and verified registry and GitHub artifacts.

**Architecture:** Treat the release as a fail-closed transaction with four boundaries: freeze and commit documentation, create and verify the atomic version bump, obtain parallel release acceptance, then publish branch and immutable tag. Local verification mirrors the main `v*` workflow without installing anything; a Windows native-artifact lock may substitute only an isolated-copy build while preserving the root build as blocked rather than green. Publication is accepted only after the tagged `release.yml` run, exact GitHub Release assets, and npm version are independently observed.

**Tech Stack:** Windows PowerShell 7 (`pwsh`), Git, pnpm 11.9.0, Node.js/TypeScript, Cargo/Rust, GitHub REST API, npm registry.

**Global Constraints:**
- This release includes the two local fast-routing feature commits already on `master` and the current documentation synchronization. It bumps only the main package from `0.6.3` to `0.6.4`.
- `package.json.ocmm.lspVersion` remains `0.3.2`.
- `crates/ocmm-lsp/Cargo.toml` and `Cargo.lock` remain unchanged.
- No `ocmm-lsp-v0.3.3` tag or platform-package publication is created.
- Use two commits: a documentation commit and `chore: bump version to 0.6.4`.
- The root version bump and generated Codex manifests stay in the same release-bump commit.
- No schema, prompt, skill, Cargo, LSP package, release-workflow, lockfile, or dependency change is in scope.
- Clear `OCMM_PROFILE`, `OCMM_NO_PROFILE`, and `OCMM_FAST` before every local generation, test, typecheck, build, or release-version gate.
- Do not install software, terminate user processes, force-push, rewrite a published tag, or use a package-version CLI.
- The existing GitHub Actions workflow performs `pnpm install --frozen-lockfile`; this local plan never runs an install command.
- Product-file edits use the orchestrator's patch tool; every Git write in this plan is orchestrator-owned under the user's existing release authorization.
- The executor must stop at the first failed mandatory gate. The only build exception is a proven live lock on a root `dist/bin/ocmm-lsp*` artifact followed by a passing isolated-copy build and wrapper smoke test.
