## Approved outcome and boundaries

Set up npm Trusted Publishing for `@dsmm/dsmm` using a new, independent `.github/workflows/dsmm-release.yml`. Use pnpm for CI dependency installation, build, tests, pack and exact-tarball publication wherever supported. Publish the already accepted frozen `0.1.2` artifact without moving its existing tag, rebuilding/repacking it, or changing its packed documentation. It does not authorize Desktop/global rollout, authentication workarounds, session repair, unrelated ocmm/LSP releases, changing global package-manager versions, or rewriting any prior release. Stop implementation before an irreversible operation if its required authority is missing.

The existing `.github/workflows/release.yml`, root ocmm/LSP versions, unrelated generated Codex bundle and root `check:release-completion` contract remain unchanged. Introduce a distinct DSMM completion checker/receipt; never claim the root checker covers DSMM. The later user request for DSMM Trusted Publishing supersedes only the earlier DSMM document's prohibition on adding this release lane; it does not relax its Docker-before-publication or immutability guarantees.

## Control and artifact contracts

Keep trusted control tooling separate from released material in every job. Use separate `control/`, `release/`, `artifacts/` and task-owned verification directories. Helpers used for validation, downloads, publication and receipts must come from the immutable workflow control SHA, never from an arbitrary release artifact, release asset or caller-provided ref. Checkouts use `persist-credentials: false` and minimal fetch scope. Do not place untrusted manifests, tag strings or asset names directly in shell expressions; validate with helpers, pass arguments as argument arrays or environment values, and treat package metadata as data.

| Mode | Event/control identity | Released material | Acceptance/provenance |
| --- | --- | --- | --- |
| Frozen bootstrap | One `workflow_dispatch` from the trusted default branch's new `dsmm-release.yml`; fixed mode, no arbitrary inputs | Hard-pinned old tag/peeled commit and exact draft asset digests above | Verify the imported local completed Docker receipt; no source build/repack/fresh-Docker claim; explicit provenance false |
| Future release | Push of a strictly validated `dsmm-scoped-vX.Y.Z` tag; workflow/control SHA belongs to that actual trusted source | Exact peeled tag commit, matching scoped package version, package packed once in that run | Fresh source checks and independent artifact Docker gate before publication; provenance true with genuine CI identity |

The dispatch bootstrap must work even though the old tag contains none of the new workflow/helpers. Resolve control from the actual workflow SHA and record it separately from release SHA. Reject dispatch from other branches, repositories or workflow identities. Hard-code `0.1.2` constants in trusted bootstrap policy; expose no user-controlled tag, SHA, digest, asset URL, repository, package name, shell fragment or alternate source input. Repeated bootstrap execution is not an implicit repair authorization.

For future tags, YAML's trigger glob is only a coarse filter. Helpers require stable SemVer without leading-zero components, the exact `dsmm-scoped-v` prefix, and tag/package-version equality. Peel the tag, check the actual event commit and workflow identity, and verify that release source is in the trusted default-branch history. Reject forks, PR events, untrusted branch refs and mismatched source. The normal path must contain the new workflow and controls at its source commit. Record workflow file/SHA, event/ref, release tag/peeled SHA, run ID and attempt; never rely solely on `target_commitish` or a tag string as source proof.

Artifact identity records contain at least repository, package name/version, tag/peeled commit, control SHA, origin (`frozen-local-bootstrap` or `ci-built`), filename, size, SHA256, SHA1, SHA512 integrity and acceptance evidence digest. Downloads are from the fixed repository and run/release identity, not caller URLs. Check size/hash before parsing. Inspect archive entries without executing scripts: reject traversal, absolute paths, unexpected links, duplicate identity entries, nested tarballs/secrets, wrong manifest/exports and the prohibited test/checkout file set. Do not extract arbitrary archive members into the control directory.

Use package-wide Actions concurrency (one DSMM publication group, `cancel-in-progress: false`) across both modes. Never cancel a publishing run automatically. Separate permissions: validation/build/Docker/registry verification use read permissions; only the exact publish job gets OIDC; only bootstrap draft import and draft staging/finalization get `contents: write`. Bootstrap import uses that capability for authenticated draft reads only. No long-lived npm secret, `NODE_AUTH_TOKEN`, token helper or legacy auth fallback is configured. Publish from an isolated artifact directory with a task-owned minimal config, not the release checkout's npmrc or the maintainer home. Preserve OIDC request variables without logging credentials. If OIDC is unavailable or rejected, fail; do not initiate an interactive maintainer login, supply a token, or escalate permissions. Pin external Actions to reviewed immutable SHAs.
