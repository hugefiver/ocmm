# Native LSP artifact staging

`scripts/stage-ocmm-lsp-binaries.ts` stages the fresh Cargo output under the expected local and target-triple names. Cargo target selection and build orchestration remain in `scripts/build-ocmm-lsp.ts`.

An existing target is left untouched only when its complete bytes equal the fresh source. Its modification time is preserved. Size alone isn't sufficient. Missing, unreadable or different targets enter ordinary replacement; replacement errors, including a lock on different bytes, propagate rather than being classified as successful staging.

Names in the `ocmm-lsp*` output family that aren't expected are removed so stale platform binaries don't enter release assets. Replacement outputs receive executable mode `0o755` on non-Windows platforms. Copy and mode failures remain failures.

Verification must exercise identical-target preservation, missing/different target replacement, unexpected-name cleanup and failure propagation. Do not terminate user processes or accept an isolated build as proof that a failed original staging operation succeeded.

Release assets, checksums and immutable-tag rules remain governed by the current [release workflow documentation](../../../README.md#release) and release controls. This artifact-staging contract doesn't authorize a release, installation, Git write or cleanup outside the build output owned by the staging operation.
