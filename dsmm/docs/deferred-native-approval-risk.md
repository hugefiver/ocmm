# 原生审批期间切换准入配置：已接受的暂缓风险

**状态：风险已接受，暂缓修复；不代表功能已修复。** 适用基线为 DSH `0.2.0-rc.2`，仅豁免下述场景的阶段性验收，不豁免其他测试失败或发布检查。

## 触发条件与影响

DSMM one-shot 委托等待原生审批期间，父 Agent 成功切换 profile 并发布新的 admission epoch；随后用户点击 Allow，DSMM 仍可能因准入代次不一致返回 `UNAUTHORIZED`。

实际 SDK 集成测试已复现：Agent、owner、工具定义和 provider 注册保持不变，批准发生一次，但子任务模型 HTTP 请求尚未发出。该问题是条件触发的可用性及审批语义缺陷，并非所有审批必然失败。暂缓不改变运行时权限，不引入跨调用授权，也不放宽取消、归属或请求撤销保护。

临时使用时避免在审批等待期间切换父 Agent 的 profile。需要切换时，先取消待审批调用，再按当前配置重新发起委托；不要无条件重跑整个父任务。

## 保留的验证与修复条件

完整回归保留在 `test/native-core-review-regressions.test.mjs`，默认以明确原因跳过；设置 `DSMM_TEST_DEFERRED_APPROVAL=1` 可重新执行。测试跳过不能计作该场景通过。

当前 one-shot 接口不公开可用于准确关联初始输入与本次启动的消息身份或 dispatch 回执。后续 DSH 版本若提供此类公开接口，或其他可验证的等效机制，应重新评估 DSMM 内部修复，优先不修改外部代码。

解除暂缓须验证：原调用在准入更新后获准并完成；采用原始调用对应的配置；后台延迟执行仍能准确关联；其他输入和后续调用不能继承豁免；取消、owner／realm、工具及 provider 身份、既有请求撤销和历史子 Agent 边界均保持有效。升级、安装、修改外部 SDK 或发布仍需单独授权。
