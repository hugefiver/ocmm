# DSMM source-content synchronization

DSMM 0.3.1 targets exactly **DSH 0.2.1-rc.2**. Source synchronization reads the committed **DSMM-owned `source-inputs/` snapshot**, never a live or historical OCMM Root fallback. Explicit maintenance refresh captures raw bytes from the Root worktree. `source-inputs/manifest.json` records the actual full Root baseline commit and the paths whose raw Git blobs differ from that baseline, including uncommitted/untracked worktree content or checkout byte differences. The captured baseline is `3b680211feeb93508b3817546f37bee2291c402b`; raw-byte `overlayPaths` do not by themselves claim uncommitted semantic changes or a new Root commit. Generated `prompts/source/manifest.json` derives `sourceRef` from that captured baseline and retains the overlay provenance. This is full-content adaptation, not short personas. The maintenance inventory lives in `scripts/source-inventory.mjs`; the generated manifest carries the actual source → artifact → consumer, source anchors, adaptation rules, canonical role/skill inventories, attribution and exclusions. Runtime uses package-relative prepared assets only; it never requires the raw snapshot, an OCMM checkout, global SDK path or maintenance compiler. Root AGENTS, Codex bundles and user/provider/model configuration are not synchronization inputs.

The raw closure is limited to the two catalog TS files, `src/hooks/config.ts`, prompt-loader/model-family assembly inputs, shared shell safety, the selected v1 role/category/workflow Markdown, and the fourteen recursive skill resource trees. The input manifest records paths and capture provenance, not content hashes or byte-length requirements. Local source, documentation and generated resources are not locked to recorded bytes. Required resources and safe regular-file paths are still checked. Third-party downloads retain their upstream integrity verification and attribution.

## Refresh, reproduce and check

Use existing Node/TypeScript/pnpm. To deliberately adopt reviewed Root worktree changes, run from `dsmm/` with the existing complete fixed-pin frontend library:

```powershell
node --experimental-strip-types scripts/source-inputs.mjs --refresh
pnpm run sync:source       # adapts the sealed snapshot; never refreshes it implicitly
```

Refresh reads the declared inputs and captures a consistent view before writing. It rejects unsafe paths, links, missing inputs and unknown destination content. Publication uses a task-owned candidate and preserves the original snapshot on failure; concurrent edits are not overwritten. Input edits do not require resealing a hash inventory. Explicit synchronization updates prepared outputs, while read-only checks report missing resources without comparing their content against generated bytes.

CI and a cold released checkout use the tag's own adapter/generator and committed snapshot by default:

```powershell
pnpm run sync:source       # optional rebuild of prepared source targets from sealed inputs
pnpm run build            # offline frontend resource availability check first
pnpm run generate:roles   # coordinated renderer owner, after build
pnpm run check:source      # read-only resource availability and path checks
```

`sync-source-assets.mjs --check` and `generate-role-assets.mjs --check` check required output availability without writing or enforcing byte equality. `check:source` combines those results with resource-reference and safe-path checks. Explicit generation still renders current source inputs and writes changed outputs; it is not a content-locking gate.

Direct regression checks do not emit shared `lib/` or presets:

```powershell
node --import ./test/prompt-source-loader.mjs --test --experimental-strip-types --test-concurrency=1 test/source-inputs.test.ts test/source-sync.test.ts
```

Regression coverage exercises resource loading, metadata generation, missing-resource errors, unsafe-path refusal, concurrent-edit preservation and publication rollback. It does not freeze source files, generated Markdown, licenses, line endings or local resources with hashes or whole-file comparisons. The resource synchronizer and role renderer remain separate maintenance entry points.

Cold rebuild needs the existing approved toolchain/dependencies and the **prepared complete frontend fixed-pin library** as well as the committed raw snapshot. Committing the raw snapshot does not deliver ignored third-party bodies. An authorized release/build owner must preserve their delivery to the cold checkout/staging surface; missing bodies or inventory fail offline with no download or older-Root fallback. Separately authorized `pnpm run sync:frontend` can materialize missing fixed-pin resources, but is never an implicit CI/build/check action. No software installation is authorized by these commands.

Source Markdown is kept in full, with precise anchored changes and an explicit DSH resource/authority boundary. Native read/glob/grep, web_search/web_fetch, write/edit, bash/pwsh and skill invocation are the tools mapped here; native read uses `file_path`. Exposed `todo_write` replaces the owning Agent's whole content/status list under its actual parallel policy; exposed `ask_user_question` provides questions, otherwise conversation does. LSP, image/browser, documentation services and native controls remain actual-catalog/route capabilities. Host compaction is not OCMM `compress`. No Task, todowrite, compress or Context7 MCP interface is invented. Template fields describe an assignment, not callable parameters. Native delegation groups preserve root/stage-owner Builder versus bounded child Builder, strict-leaf research, read-only utility restrictions and local-coordinator specialists; runtime policy enforces these boundaries.

Role IDs remain `dsmm-<name>`. `subagents.toolTopology=per-role` exposes individual `kind=role` underscore tools plus `dsmm_category`; `parameterized` exposes `dsmm_role` and `dsmm_category` with their respective admitted target enums. Empty groups have no tool. Actual arguments are `description`, `prompt`, optional `level`, deployment-authorized/exposed `route`, and capability-exposed `run_in_background`; no template grants them. Omitted/normal preserves the default route; `roleRouting.<id>.levels` contains only configured low/high/max complete routes or effort-only choices requiring exact native preflight. A complete per-call route requires paired provider/model, drops stale effort on model changes and does not silently fall back; an effort-only override must be supported by the selected native model. Route override additionally requires captured deployment `allowRouteOverride=true`. Source tier advice never generates suffix roles or fixed max effort. Target/caller/read-only/depth authority is unchanged by topology or level. Missing required planning/review capability is reported, not bypassed. Read-only planners return complete Markdown for authorized coordinator persistence. Reviewer/Oracle independence requires different observed routes, not names.

Role calls wait for the official activation result by default. Enabled background work selects `delivery:'parent'` before start using `run_in_background:true`; an accepted child/message receipt isn't execution/review completion. Running waiting calls have no handoff. Supported live children use actual native message/Queue/Steer/interrupt controls under exact-parent authority. Cold DSMM resume is unavailable without trusted live admission. Later saves don't replace a child's original locale, route or authority. No OpenCode `task_id`, guessed idempotency or automatic message resend is supplied.

Official Registry, Runtime and JSONL namespace plugins own execution/storage. No manual-runtime selector or companion is required. The assembler takes observed `SubagentRuntimeAdmissionView` readiness plus actual tools/capabilities; a catalog or responding root isn't proof of every child control. Display metadata and old logs don't restore admission. Agent-lifetime policy remains fail-closed after owner retirement; no hot-replacement guarantee is implied.

### Runtime assembler consumer interface

`buildDsmmAgentGuidance(capturedSettings, observation: DsmmPromptObservation)` is pure and installs no tools, policy, provider, RPC or locale. The integration owner registers it once in the exact admitted Agent scope, independently of the mode-gated `buildDeepworkPrompt`; do not also inject a second dynamic locale block. Use that root/child's immutable settings, never desired deployment/editor drafts or the ancestor's new admission. Persistent `buildRolePersona` contains only shared language priority, not a configured locale.

Pass `callableRoleInventory` entries (`name`, `kind`, `targets`, optional `targetParameter`) **after actual admission/provider/tool filtering**, plus current policy-filtered native `ToolSchema[]`. The assembler intersects those schemas and target enums with optional observed role availability, and lists configured levels only when the schema exposes them. A role-availability row is not proof of a tool. Pass observed `DsmmInvocationView` under `invocation: {view, routeKind:'initial'|'actual'}`: initial is a preflighted start route, actual comes from native request/status after fallback; never infer either from raw args or a role name. Runtime admission, invocation (including route), and child evidence are explicitly projected to allowed output fields; structurally compatible objects' extra properties are not serialized. Evidence field/code/effect lists are closed and limitation output is bounded.

`capabilities.continuable` observes new child creation. `capabilities.nativeChildDelivery` independently observes supported live-child delivery under this Agent's authority; a ready binding alone doesn't prove reuse or a reachable browser surface. Native user Queue/Steer requires an actually wired `nativeBrowserPrompt.surface`. Child-to-parent reporting retains exact-sender/adjacency semantics. No foreground-handoff or cold-recovery capability is advertised. Observations describe availability; exact target, operator/connection/session/lifetime and native permission checks remain execution authority.

Request routing uses generic native capabilities and admitted `modelParameters` policy. Omitted effort remains native-owned; DSMM doesn't apply brand-calibration or brand-default-effort settings. Retired fields reject with `deprecated-field`, without automatic migration. Standard supported requests use native prepared calls. The public completions seam supports custom/Pi-AI stop parameters in self-contained literal or explicit model-mapping configurations; catalog-backed raw combinations that can't be reliably reproduced are rejected for both native and DSMM parameter sources. Standard Coding and native effort encoding remain unchanged. Source provenance and fixed-pin resource integrity remain separate from configuration-version metadata, and display records don't restore historical authority.

Authored frontend router/tooling text overrides install-by-default/implicit latest behavior: inspect existing capabilities, require separate setup authorization, and report unverified evidence without hiding incomplete declared resources. Verbatim UI/UX README paths/cwd examples are superseded by the authored DSH entry: resolve the absolute native resourceBase script, require the already-active target project context, and supply an explicitly approved project-owned output-dir for persistence. The installed skill tree is never an output target; no tool cwd field or shell cd is invented. Public renderer inputs retain the old object shape with optional source metadata; only the canonical catalog requires those trusted source fields.

## Recursive resources, notices and exclusions

Every actual canonical skill tree is copied recursively, including meaningful fixtures/tests, scripts, licenses and notices. Python caches/pyc, node_modules and VCS state are excluded. Source `.gitignore`/`.npmignore` are not runtime resources and would hide meaningful packaged resources; the DSMM distribution uses its own package file inventory instead. Frontend's legacy lighthouse helper remains a reference but is not an executable QA entry point, as the canonical source itself requires. Installation, login, Git/destructive operations are not authorized by reference commands.

OCMM-derived modifications remain under the full package `LICENSE` (LicenseRef-AAAPL, not MIT-only). V1 fork comments preserve obra/superpowers lineage. Ast-grep and session tools retain their original LICENSE/SOURCE/NOTICE files; frontend ATTRIBUTION and Apache license are retained. Third-party resource attribution/pins are not replaced with project licensing.

`publish` is excluded because OCMM release identities/authority are not DSMM operations; `customize-opencode` configures another host. OpenCode-specific debugger team JSON is replaced with independent evidence responsibilities and permitted actual DSH tools, not declared N/A. Session-format references to OpenCode/Codex remain real product data, not a global name replacement.
