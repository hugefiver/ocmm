# DSMM source-content synchronization

DSH is fixed to **0.2.0-rc.2**. Source synchronization reads the committed **DSMM-owned `source-inputs/` snapshot**, never a live or historical OCMM Root fallback. Explicit maintenance refresh captures raw bytes from the Root worktree. `source-inputs/manifest.json` records the actual full Root baseline commit and the paths whose raw Git blobs differ from that baseline, including uncommitted/untracked worktree content or checkout byte differences. The captured baseline is `3b680211feeb93508b3817546f37bee2291c402b`; raw-byte `overlayPaths` do not by themselves claim uncommitted semantic changes or a new Root commit. Generated `prompts/source/manifest.json` derives `sourceRef` from that captured baseline and retains the overlay provenance. This is full-content adaptation, not short personas. The maintenance inventory lives in `scripts/source-inventory.mjs`; the generated manifest carries the actual source → artifact → consumer, source anchors, adaptation rules, canonical role/skill inventories, attribution and exclusions. Runtime uses package-relative prepared assets only; it never requires the raw snapshot, an OCMM checkout, global SDK path or maintenance compiler. Root AGENTS, Codex bundles and user/provider/model configuration are not synchronization inputs.

The raw closure is limited to the two catalog TS files, `src/hooks/config.ts`, prompt-loader/model-family assembly anchors, shared shell safety, the explicitly selected v1 role/category/workflow Markdown, and the fourteen selected recursive skill resource trees. `source-inputs/root/` preserves their actual bytes; no whole-Root copy, runtime import of Root code, extra ledger or whole-repository hash is used. The one input manifest binds paths, byte lengths and SHA-256 digests for source/resource integrity. Snapshot `.gitattributes` disables Git text conversion for `root/**`; DSMM's local `.gitattributes` also preserves prepared source prompts, skill resources and `src/skills.ts` bytes through Git checkout. Excluded frontend attribution/license inputs are supplied by DSMM's existing fixed-pin recipe, not copied and falsely claimed as consumed Root inputs.

## Refresh, reproduce and check

Use existing Node/TypeScript/pnpm. To deliberately adopt reviewed Root worktree changes, run from `dsmm/` with the existing complete fixed-pin frontend library:

```powershell
node --experimental-strip-types scripts/source-inputs.mjs --refresh
pnpm run sync:source       # adapts the sealed snapshot; never refreshes it implicitly
```

Refresh reads only the declared closure twice and compares raw bytes, path inventory and baseline provenance. A changed capture gets at most one consistency retake; continued drift fails before snapshot writes. The destination's existing parent and all ancestors must be regular directories. An existing snapshot must validate completely, including both metadata files and every raw input; dangling/live links, malformed directories, unknown entries and integrity drift are refused before mutation. Refresh writes exclusively into a new task-owned sibling candidate, loads that candidate and runs the adapter's catalog, permission/assembly anchors and adapted resource-closure checks there. It rechecks the existing snapshot before same-parent rename publication and restores the untouched original on publication failure. Unknown existing content is never deleted as a refresh repair. A failed rollback preserves the original backup and reports its location rather than cleaning it away; post-commit staging cleanup limitations are reported explicitly. Review and commit the entire refreshed snapshot, adapter changes when needed, and prepared targets together through the authorized commit owner. Missing, additional, changed, linked or non-regular snapshot inputs fail closed; source check never repairs them from Root. A stale prepared resource not in the current output inventory is a failure and must be reviewed/removed explicitly, not silently retained or deleted by sync.

CI and a cold released checkout use the tag's own adapter/generator and committed snapshot by default:

```powershell
pnpm run sync:source       # optional rebuild of prepared source targets from sealed inputs
pnpm run build            # coordinated build owner; offline frontend integrity gate first
pnpm run generate:roles   # coordinated renderer owner, after build
pnpm run check:source      # read-only regenerated byte comparison plus resource gates
```

`node --experimental-strip-types scripts/sync-source-assets.mjs --check` regenerates all source-adapted bytes in memory and compares them to prepared targets without writing. It checks inputs before targets, rather than hashing targets alone or skipping source drift. `node scripts/generate-role-assets.mjs --check` separately checks renderer output. `check:source` requires both comparisons and the actual resource/fixed-pin gates; a passing source-only comparison is not full build/renderer/release completion. Prepared targets must retain their generated bytes in the released checkout, without text-conversion filters; `src/skills.ts` retains its existing surrounding source while regenerating the metadata section.

Direct regression checks do not emit shared `lib/` or presets:

```powershell
node --import ./test/prompt-source-loader.mjs --test --experimental-strip-types --test-concurrency=1 test/source-inputs.test.ts test/source-sync.test.ts
```

These checks commit the DSMM source snapshot and prepared targets in a disposable fixture repository, then clone and execute that checkout's generator with no Root catalog/policy/prompt/skill checkout, using only the already-installed compiler. The cold Git-only clone first refuses absent ignored frontend resources. Once the already-verified fixed-pin library is delivered, check and fresh regeneration must reproduce every adapted byte, including a text-converting checkout. Cold regeneration removes every prepared target, including the frontend index, while retaining the authored `src/skills.ts` shell and genuine fixed-pin vendor library. The replay's generated index drives recipe selection, offline vendor validation and resource closure; stale prepared index bytes cannot supply the recipe or mask missing input dependencies. Missing/drifted vendor resources remain fatal before output writes. Checks also exercise raw-input tamper/missing/extra/link refusal, resealed permission-anchor and resource-closure errors, actual metadata regeneration, prepared extra-resource refusal, bounded capture drift, metadata/ancestor link refusal without outside writes, unknown-content preservation and candidate-publication rollback. For current source/native SDK prompt/tool behavior, run `test/prompt-guidance.test.ts test/skills.test.ts` through the same in-memory loader. The resource sync and role renderer remain separate entry points; coordinate shared compiled output/preset generation with its owner. Sync writes changed artifacts only; a second run must report no differences. Do not hand-edit generated prompt/source assets, skills or presets.

Cold rebuild needs the existing approved toolchain/dependencies and the **prepared complete frontend fixed-pin library** as well as the committed raw snapshot. Committing the raw snapshot does not deliver ignored third-party bodies. An authorized release/build owner must preserve their delivery to the cold checkout/staging surface; missing bodies or inventory fail offline with no download or older-Root fallback. Separately authorized `pnpm run sync:frontend` can materialize missing fixed-pin resources, but is never an implicit CI/build/check action. No software installation is authorized by these commands.

### Runtime assembler consumer interface

`buildDsmmAgentGuidance(capturedSettings, observation: DsmmPromptObservation)` is pure and installs no tools, policy, provider, RPC or locale. The integration owner registers it once in the exact admitted Agent scope, independently of the mode-gated `buildDeepworkPrompt`; do not also inject a second dynamic locale block. Use that root/child's immutable settings, never desired deployment/editor drafts or the ancestor's new admission. Pass B's `callableRoleInventory` entries (`name`, `kind`, `targets`, optional `targetParameter`) **after actual admission/provider/tool filtering**, plus current policy-filtered native `ToolSchema[]`. The assembler intersects those schemas and target enums with optional observed role availability, and lists configured levels only when the schema exposes them. A role-availability row is not proof of a tool. Pass observed `DsmmInvocationView` under `invocation: {view, routeKind:'initial'|'actual'}`: initial is a preflighted start route, actual comes from native request/status after fallback; never infer either from raw args or a role name. Runtime admission, invocation (including route), and child evidence are explicitly projected to allowed output fields; structurally compatible objects' extra properties are not serialized. Evidence field/code/effect lists are closed and limitation output is bounded.

`capabilities.continuable` observes **new child creation**. `capabilities.managedChildDelivery` independently observes **managed parent-to-existing-continuable-child delivery under this exact Agent's authority**; omitted/false does not establish reuse, even with a ready binding and native `send_message`. Model reuse guidance requires that flag, a ready unique DSMM delivery fence and the actual exposed control. Native user queue/steer additionally requires an actually wired `nativeBrowserPrompt.surface`; its name/readiness alone does not prove delivery. Existing-child delivery does not require creation/background to be enabled. Exposed native child-to-parent reporting remains separate and retains exact-sender/adjacency semantics. Supply native jobs capability and a wired `foregroundHandoff.surface` only when supported. Optional `ChildAdmissionEvidenceView` supplies original/proven fields and precise capability limitations, never extra private state. These observations describe availability; actual target, operator/connection/session/epoch/lifetime and native permission gates remain the execution authority.

DeepSeek V4 Pro/Flash guidance applies only to the exact verified provider/model pairs, uses adapter-advertised efforts and treats configured default effort as policy, not an observed request result. Ordinary root native model/effort and explicit preflighted invocation effort remain authoritative. Preset-derived max reasoning policy is not part of this calibration.

Authored frontend router/tooling text overrides install-by-default/implicit latest behavior: inspect existing capabilities, require separate setup authorization, and report unverified evidence without hiding incomplete declared resources.
