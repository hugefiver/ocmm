# DSMM roles on DSH 0.2

DSMM defines twelve unsuffixed normal roles: orchestrator, planner, plan-critic, builder, reviewer, oracle, oracle-2nd, creative, code-search, doc-search, clarifier and media-reader (each prefixed `dsmm-`). A role name is a persona and tool policy, not a model-selection claim. Reviewer is primary-model self-review; an Oracle is an external-model cross-check only when the caller explicitly selects a distinct model offered by the current DSH catalog. The second slot is priority order, not greater capability.

## Runtime surfaces

DSH 0.2's `agentPresets.register({ id, plugins })` is the native preset registry. When the host composes `agentPresets` (such as the Web profile), DSMM registers enabled roles as complete plugin compositions: persona, instructions, filesystem/search/web tools, seven bundled workflow skills, on-demand debugging, and role-specific subagent tools where appropriate. Directly selected read-only roles receive an Agent-scoped native `tools.restrict({ deny: ['write', 'edit'] })`; shell tools are not composed into those presets. The orchestrator and builder include native `@deepseek-ai/dsh-tool-subagent` instances whose `persona` and `toolFilter` actually shape each child. Read-only child filters allow repository reads/search, with web tools for doc/media roles; media image reading is available only when that tool exists in the host catalog. The provider must support persona, tool filtering and the host's depth/permission limits.

The DSH headless one-shot runner does **not** mount or select agent presets. When its startup bundle includes `@deepseek-ai/dsh-headless`, DSMM instead mounts the same role-specific subagent instances on each root Agent's tool plane. The tools remain schema-stable for DeepSeek Flash's addition-only tool catalog, but DSMM's monotonic guard rejects owned role-tool calls unless deepwork is active or a DSMM role preset is selected. Headless default sessions therefore keep their original model, tools and DSMM opt-in boundary. Role children inherit the parent's model in both headless and Web presets: DSH's standing `modelSelectionSettings` would re-register subagent tools in each child's own scope, bypassing its inherited-tool filter. DSMM keeps that setting off to enforce read-only roles. Configure a separate host tool/provider with its own verified child filter if external Oracle heterogeneity is required. DSH controls approval, sandbox, cancellation and child depth; DSMM never bypasses those controls.

Only enabled role IDs are registered, materialized and exposed as child tools. The canonical role has no suffix. DSH-specific high/low/max model tiers require an explicit profile composition or subagent model choice: no suffix presets are generated by default, and any separately declared tier must preserve the canonical role persona, readonly filter and other constraints. A profile declaration is not proof of a callable tool: inspect the running tool schema or preset registry diagnostic.

## Optional static mirror

`agent-presets/` is a renderer-checked static snapshot for inspection or profile authors, **not** a directory scanned by the DSH 0.2 registry. `presets.materialize` defaults to false. If enabled, `presets.root` writes only DSMM-owned enabled role directories; adding that path to an obsolete `agent-presets.roots` config does not enable native discovery. In the source repository, regenerate snapshots with `node dsmm/scripts/generate-role-assets.mjs` after the TypeScript build; the development generator is not included in the published package.

Materialization keeps the role-bound `.dsmm-managed-preset` marker. Foreign, mismatched, malformed or linked directories/files are never claimed. A current marker with unexpected entries fails closed; only an exact legacy `managed by dsmm` directory with the three expected regular files is updated. Disabling an enabled role removes only its owned directory. No role becomes the host default by installing DSMM.
