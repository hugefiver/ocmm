# Receiving Code Review

Treat review feedback as claims to verify, not commands to obey blindly.

1. Reproduce or inspect each finding in the current code.
2. Fix only confirmed issues within the requested scope.
3. Re-run the evidence that proves the fix.
4. Re-request only an explicitly required review or one affected by a substantive fix or new evidence. Push back with concrete code and evidence when feedback is incorrect; escalate a suggestion that would alter approved scope, safety, data, permissions or public APIs.
